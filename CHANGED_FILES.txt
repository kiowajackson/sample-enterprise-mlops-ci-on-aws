What this changes
- ResolveModel -> GetData -> Preprocess -> Score -> Postprocess.
- Preprocess applies the saved feature mapping and writes prepared/data.csv plus
  selection/selected_features.csv. No training target is required for inference.
- Score writes predictions.csv, messaging.csv and messaging_final.csv.
- Postprocess gets the original raw snapshot, saved selection, all three prediction
  files and saved config. It writes prediction_analysis.csv and summary.json.
- Training and inference data sources can differ. Defaults remain csv_direct for
  both; later set data_source=feature_store for training and leave
  inference_data_source=csv_direct in notebook 02.
- New Registry versions expose ModelMetadataUri and ModelMetadataSha256 for the
  exact metadata JSON published by Evaluate. The archive retains identical bytes.
- Existing compatible approved models can run updated Processing inference with
  model_code_source=pipeline. No training rerun is needed for that test. To expose
  metadata separately on a new Registry version, run updated Evaluate/RegisterModel.
- All four inference compute steps are cache eligible with a fixed CSV; resolution
  stays live. Downstream inputs refer to actual producing jobs, including cache hits.
- Training and inference modules remain separate. Consolidation is later refactoring.
- MLflow logging is not implemented; final analysis is currently available in S3.
