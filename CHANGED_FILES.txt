After updating the code, run notebook 02 with your existing config.json. Notebook
01 only needs rerunning for new data or ingestion. Notebook 02 defaults to
batch_runtime="both", cache_steps=True and include_hpo=False. It deploys one
training and one inference pipeline; InferenceRuntime selects one branch per run:

processing: ResolveModel -> GetData -> Preprocess -> Score -> Postprocess
transform:  ResolveModel -> GetData -> PreprocessTransform -> CreateModel
            -> Transform -> PostprocessTransform

Start two inference executions with the same ModelId and scoring CsvInputUri to
compare the modes. Processing uses uploaded code with a compatible approved
model. Native Transform uses archived code: train/package and approve a model
containing this serve revision before testing it. The image must support the
serve startup route and contain Flask/Gunicorn plus model dependencies.

Both modes call the same five-argument predict_with_model function. Transform
materializes a temporary CSV per request, selects TransformOutputFile (default
messaging_final.csv), and returns that file's columns in input ID order. Other
temporary request files are removed. Processing preserves all output files.
Compare resolved model-package ARNs when testing concurrently; keep approvals
stable while launching. Current compute caches remain enabled; registry lookup,
registration, conditions, CreateModel and native Transform are not cached.
